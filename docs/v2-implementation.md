# v2 implementation notes (2026-11-25, v2.1.1)

How the custom-game mod works on top of the v1 patches (`docs/v1-implementation.md`). Exe SHA-256 `41ab697b…bfd306`.

## Modules (host/src)

| File | Role |
|---|---|
| `uobj.*` | Native reflection: GUObjectArray `0x14507ff60`, FName ctor `0x1414f3970` / ToString `0x14150ac20`, FText from FString `0x141454760`, ProcessEvent = UObject vtable slot 0x41 (`0x141686380`). Layout: UStruct is 0x20 larger than stock (Super 0x30, Children 0x38, Size 0x40; UFunction Flags 0xa8, ParmsSize 0xae, Func 0xd0; UProperty Offset 0x44, UBoolProperty ByteOffset/Mask 0x71/0x72). `FindAll` uses an incremental class index (`IndexStep`, 12k objects per frame); entries are validated through the object array only, never by dereferencing (objects can be freed). `uo::Call` runs a UFunction by name with named parameters. |
| `steam.*` | Flat Steamworks 1.39 API from the game's `steam_api64.dll` (SteamMatchMaking009, SteamFriends015, SteamUser019, SteamUtils008). Async results polled with `IsAPICallCompleted`; callbacks 333 (lobby join requested), 337 (rich presence join) through a hand-built CCallbackBase. |
| `lobby.cpp` | Lobby state + backends (Steam lobbies; `-be1v1devlobby` file backend in `%TEMP%\be1v1-devlobby` for local tests). Drives the dormant **CustomGameScreen** through **MBCustomGameManager** fields (MemberList 0x80, Teams 0xe0, Spectators 0x110, MapRoster 0x128, CurrentMap 0x138, GameName 0x160, Privacy 0x170, MaxRoster 0x174, TeamsLocked 0x178, IsLeader 0x179). Host publishes lobby data (`teams`, `maps`, `rules`, `seq`, `state`, `addr`, …); members mirror it. |
| `ui.cpp` | Blueprint event interception by swapping `UFunction::Func` for a thunk (all Invoke paths hit it). Main menu relabel (CUSTOM QUEUE → CUSTOM GAME), lobby browser and prompts on the game's system message screen (`ShowSystemMessageInfo` with `DefaultYesNoSystemMessageScreen_C`; list rows are `PromptListButtonTemplate_C` added into its `VerticalBox_2`). |
| `settings.cpp` | Adds rule rows to the Custom Game settings panel (`Widget_ShifterOption_C` / `Widget_TickBoxOption_C` created after the panel's open transition — rows added earlier never draw values). |
| `rules.cpp` | Applies rules on every machine when the match world streams in: `MBCapturePointManagerData` PointsRequiredToWin 0x4c, InfiniteCycle 0x98, CycleActiveTime 0x9c; `MBCapturePointData` CaptureTime 0x220. Map modifiers: sets the `MapMods.ActiveMapMods` CVar string (`*0x145341278`) and calls `TrySetActiveMapModsFromCVar` `0x14102c6b0` from a hook on the manager's world init `0x14101a6d0` (the game only did this offline). |
| `game.cpp` | Teams: joiners put `?BETeam=<n>` in the join URL; the host finds it in the connection's request URL and sets `PlayerState.TeamId` (0x5d4) — fixes shared fighter rosters. Spectators (team -1): no AddPlayer event (`0x1410f9640` returns null, both callers handle it), host sets `bOnlySpectator`/`bIsSpectator` (match no longer waits for them), client calls `StartSpectating` and closes `FE_HeroSelectScreen_C` → native spectator HUD. |
| `update.cpp` | GitHub `releases/latest` of `vainstar1/project-BE` (WinHTTP, anonymous). Newer tag → native Yes/No prompt on the main menu; "Later" turns the billboard's Leaderboards line into "Update". Update: download `BE1v1.zip`, unpack with `tar.exe` (PowerShell `Expand-Archive` fallback), rename the loaded DLL to `.old`, copy new files, run `BE1v1.exe --relaunch <pid>` which refreshes `Launch_Game.exe` and restarts through `steam://rungameid/1189800` (`-be1v1direct` test runs restart Launch_Game.exe directly). |

## Lobby screen hooks (game addresses)

IsInCustomGameLobby `0x1411058f0` (false while the player stepped out with BACK, so the screen closes itself and the main menu doesn't reopen it), IsLocalPlayerLobbyLeader `0x1411059d0`, StartGame `0x14110cdb0`, menu SetPlayerTeamId `0x140fcfdc0` / SetLocalTeamId `0x140fcf9e0`, CanStartGame `0x140fbd490`, TryStartGame `0x140fd8650`, InviteFriend `0x141105390`, TryGetLocalTeam `0x14110fd30`, RequestLocalTeamChange `0x141110290`, exec LeaveLobby `0x1412f6250` / LeaveGame `0x141309e10`, GetMapList `0x141010c40` (replaced by our list: 7 CP + 7 Power Collection arenas, Dojo, `MB_DefaultRollbackMap` with a synthetic row). Blueprint events: `FE_MainMenuScreen_C.OnCustomQueuePressed` (browser), `.OnLeaderboardButtonPressed` (update), `CustomGameScreen_C` invite/leave bound events, `CustomGame_PlayerSlot_Queue_C.OnPressed_Event` (mouse team switching), `PromptListButtonTemplate_C` pressed event (list rows, LEAVE = the screen's hidden debug buttons moved into HostView/ClientView).

## Known gaps

- Steam invites and friends-only visibility are untested with two real accounts.
- Dojo settings are not carried between sessions; Power Collection score rule not wired (`MBSeedManagerActorData.SeedsRequired` 0x188 is a struct).
- Spectator HUD shows replay controls (rewind/fast-forward) that do nothing in live play.

## v2.2.0 changes (2026-11-26)

- **Performance.** `uo::FindClass` looked for unloaded classes (menu classes during a match) with a full scan of ~464k objects, ~20 ms each, several times per lobby tick: 20 ms stalls 4×/s in every match. Class objects are now indexed by the background sweep (`IndexStep`), misses are free. The class index tracks up to 64 classes and drops classes that were unloaded (Blueprint classes reload with every map). `uo::Prewarm` indexes the lobby's classes in one pass on the main menu; sweep budget 12000 objects/frame in menus, 3000 in matches. Mod cost in a match: ~0.3 ms/frame (logged every 30 s as `perf: N fps avg ...`).
- **Text chat.** `nt.usePlayfabTextChat` (int at `*0x145341e20`, default 1) sent chat through PlayFab Party, so the host never relayed it. Set to 0 → `ServerBroadcastChat_Implementation` (`0x1410c7910`) relays with `ClientReceiveChat`. Channel 0/7 = team, 1/3/5/6 = everyone, 2/4 = whisper (filter `0x1410bdda0`). In custom games the host relays team messages on channel 1 (everyone).
- **Fighter select.** Teams are set on joined players' PlayerStates right before the host's replication pass (`GameBeforeReplication`), so the first PlayerState everyone receives already has the right TeamId (before, a 0.5 s timer let both sides see each other as teammates).
- **Spectators.** Spectator mode is confirmed (`IsSpectator` + `MBWorldSingleton.bIsInSpectatorMode` +0x98d) and retried every 1.5 s; fighter select is closed only then. Replay controls (`Widget_SpectatorPlaybackControls_C`, `Widget_SpectatorReplayProgressBar_C`, `VerticalBox_ReplayProgressInfo`) are hidden; the follow camera picks the next player when it follows nobody.
- **Lobby screen.** The menu built `team max − NumQueueSlots` (0x458, 4) real team slots plus blank queue slots (builder `0x140fd9440`). `NumQueueSlots = 0` gives real `CustomGame_PlayerSlot_Team_C` / `_Spectator_C` slots. Empty places read Join / Open / Invite (host) / + Spectate; `Pressed` and `OnPressed_Event` of all slot classes go to `lobby::OnSlotPressed` (debounced). LEAVE is a new `PromptListButtonTemplate_C` copied from INVITE's style, placed above START; members get JOIN MATCH while a match runs without them. Buttons are moved only after the screen's intro animation (`IsAnyAnimationPlaying`), else the side columns freeze off-place. Members: no rename pencils, focus on their own place. Info line under the title: map / mode / size / privacy.
- **Settings panel.** Spectators row restored and synced with `SpectatorTeam.Max`; rows: Team Size, Points to Win, Cells to Win, Objectives (rotation), Capture Speed, Map Mods (Off / Choose / All; per-mod rows only for Choose).
- **Rules.** Absolute targets: CP `MBCapturePointManagerData.PointsRequiredToWin` (+0x4c), Power Collection `MBSeedManagerActorData` +0x1b0 (base value of the `SeedsRequired` struct at +0x188, 50 on every map). Applied in the map-mods world-init hook (full scan) and re-applied for 10 s, keyed by world. Lobby protocol 3 (rules encoding changed).
- **Browser.** Cached list refreshed in the background on the main menu (20 s, 6 s while open), opens instantly, rows update in place (`ui::UpdateList`). Friends' lobbies de-duplicated. Last row: OFFICIAL CUSTOM QUEUE (passes `OnCustomQueuePressed` through to the game). Billboard label CUSTOM GAMES.
- **Official leaver penalty.** Leaving a match early sends PlayFab `Account_AddLeaveReasonSingle_Leave` (`0x14110b830`) → official penalty. Blocked when `lobby::Active() || net::CustomMatch()` (the match was entered through the mod's travel). The official penalty message (`0x1410fbb60`) is skipped in custom games.
- **Other fixes.** `net::Travel` works on joined players (it waited for a game mode only the host has: "host left" never returned members to the menu). New members join the smaller team, or spectate when both are full; a re-appearing member keeps the team they asked for.
- **Hooking rule.** `ui::OnEvent` (UFunction::Func swap) only for functions run through ProcessEvent. A native function called from Blueprint script runs on the caller's frame and hangs the game if swapped: hook it natively (MinHook).
- Harness: `matchtest.ps1 [-Map N] [-Rules ...]`, `spectest.ps1 [-MidMatch]`, `BE_RES=1600x900` env for bigger windows; dev commands `lobby rules|rejoin|leavebtn`, `ui chat|pick N|setrow R I|dump Class off len`.

## v2.3.0 changes (2026-11-26): 3-4 teams, Knockouts Only scoring, Steam avatars

Lobby protocol 4 (rules string gained `teams`, `kos`, `koOnly`). Settings: Teams (2-4), Team Size ("2v2v2"), Scoring (Objectives / Knockouts Only), KOs to Win (Knockouts Only). 3-4 teams play Objective Control (a Power Collection pick plays the same arena's Objective Control version: the seed manager only has team 0/1 cell counters).

- **Simulation** (`host/src/teams.cpp`, all machines, deterministic; `teams::Active()` = 3-4 teams):
  - `MBCommonLevelObjectActorData.NumTeams` (+0x30) = teams, written at world init (`rules.cpp`). The CLO sizes TeamInfoArray/TeamStatsArray from it; with 2, a team-2 player made the match end with NotEnoughPlayers.
  - **Capture points** (`CapUpdate 0x1429de030`): the game counts capturers as team 0/1 and moves one progress value (-1 team 1 .. +1 team 0, state +0x7b4). Per point and frame it runs with two sides: side 0 = holder (owner, or whoever has the partial progress), side 1 = every other team on the point (point's TouchingActors +0x780, `CanCapture 0x1429c2780`). Players' and the point's team ids are swapped for the call and restored. `CapturedBy 0x1429c34d0` gets the real team (and the real previous owner); an owner change made elsewhere during the call (turning neutral) is translated from side ids. Progress is then stored from the holder's side (positive); a neutral point's partial holder is encoded in the progress value's low bits (multiples of 2^-22 over a 2^-18 grid), so it rewinds with rollback. `GetTeamProgressBarFraction 0x1429cb170` answers any team the same way (display). Tested: team 2 captures, team 0 neutralises and captures; identical on both machines.
  - `Points` (CP manager state +0x90) grown to N in AddPoints `0x142a58120` (bounds-checked by the game). KO handler `0x142a58710` scores `victim team == 0 ? 1 : 0`: while it runs, AddPoints gets the attacker's team (victim/attacker info: team +0x30, valid +0x40). AddPoints inside a capture update maps side ids to real teams.
  - Winner check `0x142a5bce0` (compares Points[0..1] only, with overtime): N-team version; calls the original with a 2-entry table in which "team 0" reached the target so the game ends the match its own way. Game-ended event (`FireEvent 0x140395190`, id 1; LosingTeam +0x28, Team0Score +0x2c, Team1Score +0x30) carries each machine's own view (screens compute `defeat = LosingTeam == myTeam`); the match flow (`0x141050810`, bGameEndedInDefeat +0x1bb) reads a copy from the confirmed frame and gets the same patch.
  - Respawn pad choice `0x1429deaf0` (spawn data TeamId +0x3c vs player team): teams 2/3 use team % 2.
  - `IsSameTeam 0x142a8dd50`: map objects (no top-level owner, not MBPlayerState) treat the paired team as owner, so team 2 passes team 0's spawn force field (`BP_ForceField_Proxy_C`) and gets the base's protection. Players (and what they own) stay enemies.
  - **Knockouts Only** (`rules.koOnly`, any team count): capture manager data PointsOnPlayerDeath (+0x30) = 1, portal/tick/capture points 0, CycleWaitInitial (+0x94) = 1e8 (objectives never open), PointsRequiredToWin = KO target (host's choice, else 5 x team size + 5). Loading screen and fighter select say "Team Brawl".
- **HUD**: the capture point manager widget update `0x141255150` only runs when Points.Num == 2 and maps ally/enemy as team 0/1: it gets a 2-entry view (this player's team, leading other team). Fighter-select team scores `0x1410124f0` likewise. With 3-4 teams a row under the score bar lists every team's score in its colour (`Widget_PointsManager_C`, added to `VerticalBox_0`). Knockouts Only hides the objective timer line and icons.
- **Colours**: teams 0-3 = blue, red (the lobby's own 0.067/0.631/0.875 and 0.824/0.039/0.055), yellow, green (`teams::Colour`). Lobby slots: after-hook on `CustomGame_PlayerSlot_Base_C.Get_Background_ColorAndOpacity` (the return value is the thunk's `res` pointer, not in the locals). Enemies of teams 2/3: floating health bar `EnemyColor` (colours the name; the bar fill stays red).
- **Shared spawn rooms**: zone = AABB of a base's spawn point states (+0x2c0) + 550 (XY). A player of the paired team inside it is hidden on this player's screen (`SetActorHiddenInGame` on the proxy pawn; team = MBProxyActor.LastFrameTeamId +0x438). Visual only.
- **Lobby screen**: the menu builds columns from TeamOrder (+0x448), containers (+0x480), queued containers (+0x490), slot lists (+0x4b0, 0x20 each). Teams 2/3 get new VerticalBoxes (StaticConstructObject `0x1416aac50`) under the columns of teams 0/1 (2x2 grid). Hooks: GetTeamMaxPlayers `0x141100bb0`, GetTeamMembers `0x141100be0` (both bounded to -1..1). Team 3 takes the left column layout (slot `WidgetSwitcher_0` index 0, re-applied after the slot's Tick).
- **Loading screen**: built from the lobby member list (`0x141086330`, team 0/1 lists at manager +0x180/+0x190, entries 0x40, avatar +0x10); with 3-4 teams it shows "my team vs everyone else" (member list temporarily reordered/remapped). Widget refresh `0x141084af0`. Loading tips are set through their inner TextBlocks: the bubble's UpdateBubbleText crashed the loading screen (another thread draws it during the load). `ui::TextToString` refuses FTexts without text data (crashed in the engine).
- **Steam avatars** (`host/src/avatars.cpp`): lobby members have no online-id object, so the game's avatar requests (Xbox gamerpics anyway) never start. Steam `GetLargeFriendAvatar` RGBA -> PNG in `%TEMP%\be1v1-avatars` -> `KismetRenderingLibrary.ImportFileAsTexture2D` -> slot `Icon`/`Icon1` and loading screen entries. BMP crashes the importer (24-bit -> PF_Unknown -> divide by zero). Slots are matched to members by name (`SlotMember`; also fixes the host moving other players by clicking them).
- Harness: `teamtest.ps1 -T1 -T2`, `brawlko.ps1` (KO with Super Powered), `captest.ps1` (capture with All Objectives) + `retake.ps1`, `steer.ps1 -Pawn -X -Y` (walks with posted keys; camera fixed so W=-Y, A=-X on Train base A), `pos.ps1`, `waitstate.ps1`; dev `lobby forceteam N`, `lobby teams N size`, `testbinds` (F13-F16 attacks), `noafk` (no idle kick in this match), `netid`.
- Known gaps: Power Collection with 3-4 teams; the loading screen's 4 name plates per side (2v2v2v2 and larger list the first 4 opponents); the health bar fill of teams 3/4 stays red; damage between paired teams inside a shared spawn room depends on the base's own protection (they are invisible to each other there).

## v2.3.1 (2026-11-26): lobby screen frame rate fix

v2.3.0 dropped the lobby screen to ~1 fps with real Steam lobbies. The lobby's labelling pass (a few times a second) looked up widgets by name in slots that don't have them (the hidden official-queue slots: no picture, no name texts; spectator slots' texts aren't Blueprint variables); the fallback searched every widget in the game each time, and v2.3.0 added the avatar lookups that hit it constantly. Now: `Named()` uses `UserWidget.GetWidgetFromName` (the widget tree's own lookup) instead of a search, queue slots are skipped, avatars go only on `CustomGame_PlayerSlot_Team_C` slots (Icon/Icon1 by property offset), and `avatars::Show` sets a brush once (brush ResourceObject read through reflection). Lobby screen with 4 teams and the settings panel: ~240 fps alone, worst lobby update ~50 ms once when the screen opens. Team Size labels are "1 Player".."4 Players" (the option row doesn't redraw relabelled options).
